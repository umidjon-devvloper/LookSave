# 2026-11-21 — App Store 4.3(b)/5.2.1 uchun kontent tozalash

App Review'ning 6-rad etilgan ariza (72-build, 2026-11-19, iPad Air 11" M3)
uchun jonli katalogdan kontrafakt signallarini olib tashlash.

## Ishga tushirish tartibi

VPS'da, prod `.env` bilan:

```bash
cd /var/www/looksave/apps/api
SQL_DIR=scripts/sql

# Ketma-ket, har biri tranzaksiyali
psql "$DATABASE_URL" -f $SQL_DIR/2026-11-21-non-partner-brands.sql
psql "$DATABASE_URL" -f $SQL_DIR/2026-11-21-luxury-brand-names.sql
psql "$DATABASE_URL" -f $SQL_DIR/2026-11-21-model-suffix-rename.sql
psql "$DATABASE_URL" -f $SQL_DIR/2026-11-21-description-sanitize.sql
psql "$DATABASE_URL" -f $SQL_DIR/2026-11-21-demo-user-role.sql
```

## Nima o'zgaradi

| SQL | Ta'siri |
|---|---|
| `non-partner-brands` | `brands` jadvalidan Nike/Adidas/Zara/Puma/NB o'chadi; shu brendlardagi mahsulotlar `brand_id = NULL` bo'ladi |
| `luxury-brand-names` | Luxury do'konidagi 47 ta sarlavhadan `Hermès`/`Loro Piana`/`Louis Vuitton` so'zlari olib tashlanadi |
| `model-suffix-rename` | «... — model 23» → «... №23» (katalogdagi 24+ dummy ko'rinishli sarlavha) |
| `description-sanitize` | Tavsiflardan «kopiya», «uslubidagi», brend nomlari olib tashlanadi (kontrafakt signali) |
| `demo-user-role` | Demo akkaunt (+998937844572) roli `store_owner` → `customer`. Login'da sotuvchi paneliga tushmaydi. |

## Qaytarish (kerak bo'lsa)

- **non-partner-brands** — qaytarib bo'lmaydi (brand_id'lar yo'qoladi). Qayta `INSERT INTO brands ...` qilish mumkin.
- **luxury-brand-names** / **model-suffix-rename** / **description-sanitize** — qayta sarlavhalarni yozish kerak. `pg_dump` bilan avval zaxira olish tavsiya qilinadi.
- **demo-user-role** — `UPDATE users SET role = 'store_owner' WHERE phone = '+998937844572';`

## Zaxira tavsiyasi

Ishga tushirishdan oldin:

```bash
pg_dump "$DATABASE_URL" --table=products --table=brands --table=users \
  --data-only > /tmp/looksave-pre-4.3b-cleanup-$(date +%F).sql
```
